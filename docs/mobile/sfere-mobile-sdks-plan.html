Building the Sfere iOS and Android SDKs

Two native SDKs that collect first-party fan events in mobile apps and send them to the Sfere ingestion endpoint. They send the same payload as the existing browser and Node SDKs, and include CleverTap-style app events, renamed to fit Sfere's naming rules.

Written 2026-10-13. Based on the ingestion platform's iOS and Android docs, the CleverTap events reference, and fanfinity/sfere-sdk (README, ARCHITECTURE, WIRE-CONTRACT, EVENTS, HTTP-API, RELEASING, CI). The step checkboxes save in this browser only.

Moved to docs/mobile/ on 2026-10-18. The repos ended up as fanfinity/sfere-ios-sdk and fanfinity/sfere-android-sdk; this plan calls them sfere-ios and sfere-android. The ingestion platform's vendor name was replaced with "the ingestion platform", following this repository's rule.

1. Summary

What we ship

SfereAnalytics (Swift Package) in repo fanfinity/sfere-ios, and io.sfere:analytics (Android AAR) in repo fanfinity/sfere-android. These names come from WIRE-CONTRACT §7.

How we build it

The same pattern as the browser SDK. Segment's open-source analytics-swift / analytics-kotlin stay unmodified as dependencies (MIT, not a fork), and Sfere adds plugins on top. The ingestion platform's own mobile docs use the same two libraries.

What makes it Sfere

Click IDs and campaign data from deep links, sessions, consent, dedup IDs, the library stamp, settings built into the code, and nothing sent to any third-party host.

How we know it works

Unit tests, contract tests against the existing mock ingestion server, simulator and emulator tests in CI, a staging smoke test, then a beta in one internal app before anyone else gets it.

The contract already exists.

docs/WIRE-CONTRACT.md in the JS repo is the source of truth for the mobile SDKs too. It has a Mobile column whose rows are all marked planned, and it says: "A new SDK is done when its events match this page." This plan turns that column into work items and tests. As each item ships, update that column from planned to live.

2. What the ingestion platform does, and what Sfere adds

The ingestion platform doesn't write its own mobile SDKs. Its iOS and Android pages just point Segment's analytics-swift and analytics-kotlin at its own hosts. Sfere's browser SDK does the same with analytics-next, then adds an enrichment plugin. The mobile SDKs copy that: the platform's setup, plus Sfere's plugins.

4. Public API (target shape)

The facade hides the base library, so the base library can be replaced later without breaking client apps. Both platforms use the same method names, and the arguments follow the browser SDK.

Swift
import SfereAnalytics

// AppDelegate.didFinishLaunching
let config = SfereConfiguration(
    writeKey: "keyId:secret",                 // browser key
    host: "https://ingest.example.com"        // https origin, no path
)
config.sessionTimeoutMinutes = 30
config.consent = ["analytics": true, "advertising": false]
Sfere.setup(config)

Sfere.shared.identify(userId: "user_123", traits: ["email": "fan@example.com"])
Sfere.shared.screen("Match Center", properties: ["match_id": "42"])
Sfere.shared.track("add_to_cart", properties: [
    "currency": "SAR", "value": 89.99,
    "items": [["item_id": "sku_12345", "item_name": "Away Jersey", "price": 89.99, "quantity": 1]]
])
Sfere.shared.purchase(Purchase(transactionId: "order_98765", currency: "SAR", value: 256.96, items: items))
Sfere.shared.setConsent(["analytics": true, "advertising": true])
Sfere.shared.openURL(url)                         // deep links and universal links
Sfere.shared.setEnabled(false)                    // opt out
Sfere.shared.reset()                              // logout
Sfere.shared.flush()
Kotlin

// Application.onCreate

Sfere.shared.setConsent(mapOf("analytics" to true, "advertising" to true))

5. Event catalog: CleverTap events mapped to Sfere

Decided 2026-10-13: GA4 snake_case.

CleverTap uses Title Case names and its own purchase shape (Charged with Items and Amount). Sfere's founder decision #3 fixes GA4 snake_case names with properties.items[], so one instrumentation can feed analytics and server-side ad destinations. This plan keeps CleverTap's coverage and uses Sfere's naming. For example, Charged becomes purchase.

auto sent by the SDK helper SDK method the app calls from its own handler app app calls track with the documented name server belongs in the Node SDK / HTTP API out not applicable to a client SDK

Property rules (borrowed from CleverTap and WIRE-CONTRACT)

  • Event names are at most 128 characters, snake_case, and use GA4 names where one exists.
  • messageId is unique, uses only [A-Za-z0-9._-], and is at most 64 characters. The library's UUID meets this. Add a test for it.
  • value is a number, and currency is an ISO 4217 code whenever value is set.
  • Allowed types are string, number, bool, nested objects and arrays. Following CleverTap's limits, debug mode warns about arrays longer than 100 and strings longer than 512 characters. Nothing is dropped silently.
  • Keep property names flat and predictable, because every distinct name becomes a warehouse column.

8. Testing plan: before anyone else uses it

Five layers, from fast to slow. Layers 1 to 3 run on every PR. Layers 4 and 5 run before every release.

Layer 1: Unit tests (seconds, every PR)

AreaCases
ConfigA host with a path is rejected, http is rejected in release builds, the apiHost string comes out right, and the default values are correct.
SessionThe same id within the timeout, a new id after it (fake clock), foregrounding resets the idle timer, the id survives a restart, and session_started fires once per rotation.
Consent / traitsConsent is left out when unset, applies from the next event, and survives a restart. Traits are carried to later events, and reset() clears them.
DedupThe caller's value is kept, the default is messageId, and the field is never added to non-track events.
ParserEvery row of the shared URL fixture, fbclid → fbc format, a newer click replacing an older one, unknown params ignored, and broken URLs not crashing.
Rename / sanitizerEach lifecycle name maps correctly. _metadata is gone, integrations is gone unless the caller set it, and only allowed clientIds keys are left.
Ad ID gateATT denied, not determined or restricted: no IDFA. Advertising consent false: no GAID. Never zeros.
TransportUsing MockWebServer (Android) or URLProtocol stubs (iOS): Basic auth header present, writeKey in the body, retries on 503/429 with backoff, no retry on 400/401, at most 100 events per batch.
Concurrency1,000 events from 10 threads: none lost, no duplicates, no crash.

Layer 2: Contract tests against the mock ingestion server (every PR)

The SDK runs in the test process or on the simulator, sends events to mock-ingest.mjs, and the test reads GET /__events. Each payload must match its golden fixture and the WIRE-CONTRACT rules.

# from a checkout of fanfinity/sfere-sdk: ingest listens on http://127.0.0.1:4311
node packages/browser/test/e2e/mock-ingest.mjs

curl -s http://127.0.0.1:4311/__events | jq '.[-1]'   # last request received
curl -s -X POST http://127.0.0.1:4311/__reset          # clear between tests
Reaching the local mock from a simulator or emulator
  • Both base libraries add https:// to the host. In debug builds only, the Sfere facade lets host be http://… and rewrites the scheme in the request layer (requestFactory).
  • iOS simulator: 127.0.0.1 is your Mac. Add NSAllowsLocalNetworking to the sample app's ATS settings, in debug only.
  • Android emulator: your Mac is 10.0.2.2. Allow cleartext traffic to that address with a debug-only network_security_config.xml.
  • Physical devices: bind the mock to 0.0.0.0 and use your Mac's LAN IP, or put Proxyman or mitmproxy in front of staging.

Layer 4: Real devices and staging (before every release)

  • Device matrix: the oldest and newest supported iOS, at least one older iPhone, the oldest and newest supported Android, a low-memory Android, and one Samsung and one Xiaomi phone (both are aggressive about killing background apps).
  • Network capture: a 10-minute session through Proxyman or mitmproxy. Every request goes to {host}, with zero requests to segment.com or segment.io.
  • Staging smoke: every event in §5 with the browser key on /v1/batch/b, okEvents == receivedEvents, and the events show up in the staging warehouse with no new columns beyond the ones approved.
  • Same as the browser: send add_to_cart from the browser SDK and from each mobile SDK, then compare the stored rows field by field. The only differences should be platform fields (page vs app/device/os).
  • Cost to the host app: how much the SDK adds to binary size (set a budget after the first build), time added to cold start (target under 10 ms on the main thread), and memory with 10,000 queued events.
  • Store checks: an Xcode privacy report with no warnings, a TestFlight upload accepted, and a Play pre-launch report with no SDK crashes or policy warnings.

Layer 5: Beta pilot (before 1.0.0)

  • Put 0.1.0-beta.x into one internal Fanfinity app on TestFlight and Play internal testing, for one to two weeks.
  • Compare daily counts of opens, screens and purchases with the analytics the app already uses. Aim for a difference within ±5%, and investigate anything bigger.
  • The crash-free rate must not drop, and no crash may have an SDK frame at the top of its stack.
  • Someone who didn't build the SDK adds it to a blank app using only the README, in under 30 minutes. Fix every place they get stuck.

10. Distribution: how client developers get it

OptioniOSAndroidTrade-off
Public, from 1.0.0Swift Package Manager from a public sfere-ios repo (tags are versions)Maven Central under io.sfere. Requires a DNS TXT record on sfere.io to prove the namespace, and GPG-signed artifactsEasiest for clients: no tokens. The code is visible, which is normal for client-side SDKs (Segment's and CleverTap's are open source).
Private, during betaSPM from a private repo, so each client needs GitHub accessGitHub Packages Maven, so every client needs a GitHub token with read:packages, even just to install itFine for Fanfinity's own apps, but adds friction for outside developers.
Binary-onlyXCFramework attached to the releaseAAR fileHides the source, but loses automatic updates and makes adding the dependency harder.
Decided 2026-10-13: private now, public later.

During beta, the SDKs stay private (SPM from a private repo, and GitHub Packages Maven), so only Fanfinity's own apps use them. At 1.0.0 they move to a public SPM repo and Maven Central. Start the io.sfere namespace check on Maven Central early, because it needs a DNS record on sfere.io. Keep the repo history free of secrets from day one, so making it public later is just a visibility switch.

Skip CocoaPods. Its trunk is scheduled to become read-only in December 2026, and SPM is now the standard.
